# 协同剪贴板（局域网）

浏览器里输入相同房间号，就能在多台设备之间共享内容 —— 文字、图片、纯文本文件都行。
三种通信方式（HTTP 轮询 / SSE / WebSocket）各实现一遍，并且可以**随时热切换**，
切换时信息窗口一帧都不会丢。

> 对应题目：**题目 2 · 前后端综合工程**（局域网协同剪贴板）
> 当前进度：**前端完成**，后端为开发桩（见下方「当前状态」）。

---

## 一、项目简介

同一局域网下（不需要外网），一台电脑跑服务，手机 / 平板 / 电脑用浏览器打开同一个地址、
输入**相同的房间号**，即可共享同一份内容。消息以聊天流形式呈现，每条横向占满信息窗口。

界面分四面：

```
┌──────────────────────────────────────────────────────────────────────┐
│ 上：品牌 · 房间号 · 当前组合(CH×模式)   [纯文字│剪贴板读取]   昵称·状态  │
├────────────┬──────────────────────────────────────┬──────────────────┤
│ 左：三种传输 │        信息窗口（聊天流，唯一）        │ 右：在线成员       │
│  01 轮询    │  每条消息横向占满，带"从哪条管道来"标记  │     房间/服务信息  │
│  02 SSE  ●  │                                      │     历史记录(SQLite)│
│  03 WS      │                                      │                  │
├────────────┴──────────────────────────────────────┴──────────────────┤
│ 下：输入源（纯文字模式＝输入框＋图片＋文件；剪贴板模式＝监听状态条）      │
└──────────────────────────────────────────────────────────────────────┘
```

**2 种输入模式 × 3 种传输方式 = 6 种组合**，但是：

> 六个组合共用**同一个信息窗口、同一份历史**，切换的只是"消息怎么送出去"。

### 局域网内是怎么连上的

```
   手机 192.168.1.x ─┐
                     ├─ 同一个网段(192.168.1.0/24)、同一个 WiFi
   平板 192.168.1.x ─┘        ↓ 直接二层通信，不经过路由器转发
                       你的电脑 192.168.1.14:8000
                       （Node 监听 0.0.0.0，即所有网卡）
```

1. **每台设备由路由器 DHCP 分到一个同网段 IP**（`192.168.1.x` / 掩码 `255.255.255.0`）；
2. 手机访问 `192.168.1.14` 时，先按掩码判断"同网段" → **不找网关**，直接 ARP 问
   "192.168.1.14 的 MAC 是多少"，拿到后在这条 WiFi 链路上直接发帧；
3. TCP 三次握手到 `192.168.1.14:8000`，内核把连接交给**监听 `0.0.0.0:8000`** 的 Node 进程；
4. 页面里的 JS 再用**同一个地址**建 WebSocket（`ws://192.168.1.14:8000/ws/1001`）——
   只是换了协议，地址不变。所以前端一律用相对路径 + `location.host` 构造地址，**不能写死 localhost**。

**`127.0.0.1` / `0.0.0.0` / 具体 IP 的区别**

| 监听地址 | 含义 | 谁能连上 |
| --- | --- | --- |
| `127.0.0.1` | 只绑 loopback 网卡 | **只有本机**（流量根本不出网卡） |
| `0.0.0.0` | 绑所有网卡（INADDR_ANY） | 本机 + 局域网内能路由到这台机器的设备 |
| `192.168.1.14` | 只绑那一块网卡 | 局域网内能到达该地址的设备 |

**连不上的四种常见原因**

| 现象 | 原因 | 解法 |
| --- | --- | --- |
| 手机转圈/超时 | 服务只监听了 `127.0.0.1` | 改成 `0.0.0.0`（本项目默认） |
| 本机能开、手机不行 | Windows 防火墙拦入站 | 首次运行弹窗选「允许专用网络」；误拒了去高级防火墙放行端口 |
| 之前能连、现在不行 | DHCP 换了 IP | 看启动横幅里的新地址；或在路由器里绑静态 IP |
| 同 WiFi 也连不上 | 路由器开了 **AP 隔离**（客户端隔离） | 用手机热点，或关掉隔离 |

`src/net.js` 负责把地址找出来并打印：跳过 `127.0.0.1`（loopback）、
跳过 `169.254.x.x`（APIPA，说明该网卡没拿到 DHCP）、把虚拟网卡（VMware / Hyper-V / WSL / 蓝牙）
排到最后并标注「多半连不上」。

## 四、基本设计

### 4.1 六组合互通：三个正交的东西

```
   输入源（2 种模式）          唯一数据源                管道（3 种传输）
   纯文字输入框  ─┐       ┌────────────────┐       ┌─ 轮询 ─┐
                 ├──────→│  MessageStore  │←──────┤─ SSE  ─┼──→ 服务端
   剪贴板监听    ─┘       │  按 seq 去重    │       └─ WS  ──┘
                          └────────┬───────┘
                                   │ 只读订阅
                              ┌────┴─────┐
                              │  信息窗口 │   ← 只认 store，不认传输
                              └──────────┘
```

三条规则：

1. **传输只负责"灌"**：三种传输把消息交给同一个 `store.apply()`，它们不知道窗口长什么样；
2. **模式只负责"产"**：两种输入模式把内容交给同一个 `send()`，它们不碰窗口，也不碰传输；
3. **窗口只订阅 store**：切换传输或模式时，窗口没有任何"清空 / 重建"逻辑 —— 所以内容天然连续。

### 4.2 为什么按 `seq` 去重就能解决一切

服务端给每条消息一个**单调递增的 `seq`**，`MessageStore` 用它当主键合并：

- 同一条消息可能从三条路到达（POST 的响应、SSE 推送、WS 广播），窗口只显示一份；
- **切换传输时不需要任何同步逻辑**：新管道带着 `since = store.lastSeq` 接上，只补差额；
- 断线重连同理：WS 的 `hello` 带上本地最大 seq，服务端把断线期间的消息补齐即可。

### 4.3 三种传输的差别（代码里如实体现）

| | 下行 | 上行 |
| --- | --- | --- |
| HTTP 轮询 | 每 1.5s `GET /api/snapshot?since=` | `POST /api/messages` |
| SSE | 一条 `EventSource` 长连接，服务器主动推 | **仍是 `POST`**（SSE 单向） |
| WebSocket | 同一条双向连接 | **走 socket** |

SSE 的断线补齐：`EventSource` 会自动重连，但不会补发断线期间的消息，
所以每次 `onopen` 都额外拉一次 `since=本地最大 seq` 的 REST 差额。

> 完整展开（**为什么只有 WebSocket 算双向**、"能收能发"和"双向"的区别、服务器能不能主动开口、
> F12 怎么一眼验证）见 [对话记录 01 · 实现过程](对话记录-01-实现过程.html) 的 Q7–Q11。

## 五、设计思路（本人的口径）

1. **先定结构，再定风格。** 一开始把"侧边栏 3 板块 × 2 小栏"理解成功能分区，是错的；
   真正的结构是**左＝三种传输方式、上＝纯文字/剪贴板读取 选择栏**，2×3＝6 种组合，中间一个信息窗口。
   读 `EasyPub-New/index.html` 是为了看它的**结构写法**（侧边栏导航 `.nav-item` + 分段控件 `.lib-seg`），
   不是照搬配色。
2. **六个组合必须共用一个窗口。** 所以不给每种组合做一套页面，而是把"输入源 / 数据源 / 传输管道"
   拆成三个互相不知道对方存在的东西，窗口只认数据源。切换管道＝换管子，切换模式＝换底栏。
3. **历史记录不是另一套数据。** 它就是同一份数据源在服务端的持久化副本，所以天然六种组合共享。
4. **消息按 `seq` 去重**，是让"换管子不丢内容、不断线补差额、重复到达只显示一次"这三件事
   用同一套机制解决的关键。
5. **风格选"精密仪表"**：暖炭灰机箱 + 单一琥珀强调 + LED 电平梯 + 衬线读数。
   左侧三种传输的电平梯让"谁费流量"一屏可见；顶栏电平条 + `msg/s` 读数是实时仪表；
   右侧成员的信号格表示活跃度。
6. **消息行标记"从哪条管道来"**（POLL / SSE / WS / CLIP / RESTORE），
   这样六个组合共用窗口这件事在界面上是**看得见**的，而不是只写在文档里。

## 记录规则（本项目约定）

1. **分开装**：原始记录 / 叙事 / 总结 / 素材是四类东西，各存各的文件，不合并；
2. **原汁原味**：对话记录由脚本从会话原始日志抽取，问题与回复**按原文保留**；
3. **不人工复述**：要原始记录就用脚本重新抽，不靠记忆写 —— 复述必然走样；
4. **按说话人分色**：我的话琥珀、AI 的话蓝色，扫一眼就知道哪句是谁说的；
5. **对话记录出 HTML 不出 Markdown**：markdown 标准里没有颜色，颜色只能靠内嵌 HTML，
   而很多阅读器（浏览器直接打开、记事本）不渲染内嵌 HTML，会把 `<span>` 原样显示出来 ——
   一片标签谁都看不懂。所以这份记录**直接生成单文件 HTML**，双击就能看，
   页面自包含、不依赖网络、不依赖任何库。

## 抽取方式（可复现）

```bash
node dev/make-transcript.mjs <session.v4.jsonl.zstd> 对话记录-01-实现过程.html \
     --from "先给我出一版ui设计稿" \
     --skip "我的问答页进readme吧" "开始后端，一步步来" \
     --to   "现在你先分两个板块写"
```

- `--from` 从哪一条**开始收**（前面的选题与范围讨论不要）；
- `--skip A B` **跳过中段**（从含 A 的那条到含 B 的那条之前，这里是"怎么整理文档"那段）；
- `--to` 到哪一条**为止**（本次整理文档的讨论不要）。

普通文档（开发经历那类）用同一个渲染器，走另一个入口：

```bash
node dev/make-doc.mjs dev/docs-src/开发经历.md 开发经历.html "副标题"
```

两个脚本共用 `dev/md2html.mjs` 里的 markdown 渲染器（零依赖，自己写的）：

| 文件 | 作用 |
| --- | --- |
| `dev/md2html.mjs` | markdown → HTML 渲染器 + 共用样式 `BASE_CSS`（两个脚本共用一份） |
| `dev/make-transcript.mjs` | 会话日志 → 分色对话记录 HTML |
| `dev/make-doc.mjs` | 普通 md → 带目录侧栏的文档 HTML |

> **doc 的源文件放 `dev/docs-src/`，生成好的交付物直接放主目录** —— 免得同一份内容
> 有 md 和 html 两个版本、时间一长就不一致。（原来放在 `docs/` 里，后来按"文档全部摊在主目录
> 一眼能看到"的要求取消了那个目录。）

会话日志由**多个 zstd 帧拼接**而成，Node 的 `zstdDecompressSync` 与流式接口都只解第一帧，
所以脚本自己走了一遍 zstd 帧结构逐帧解压，再从 JSONL 里按 `type` 抽取：

- `user/message` 且 `source.kind === 'user'` → 我真正输入的消息（系统通知类的全部剔除）；
- `assistant/message` → AI 回复的**可见文本**逐字保留，工具调用只留一行摘要（避免动辄几 MB 的参数）；
- `ask_user_question` 的选项结果 → 单独渲染成"我（选择）"块，保留决策过程。

渲染上有三个**踩过才知道的坑**（都在脚本里注释了）：

| 坑 | 后果 | 修法 |
| --- | --- | --- |
| 给 AI 小标题换色时不分代码块 | 代码块里本来就写着 `###` 级别的东西（README 目录树、markdown 示例），会被染色改坏 | 渲染时跟踪 ``` 围栏，围栏内一律不动（实测 112 个围栏、0 处误染） |
| 段落按 markdown 规则合并成一行 | **ASCII 结构图被压扁成一坨**（第 1 块就是） | 原文是"裸文本"不是规范 markdown：段落保留换行 + `white-space:pre-wrap`，长行照样自动折行 |
| 行内代码不做保护 | 代码里的 `*` `[` 被后面的规则误伤，`**` 会漏出来 | 先把 `` `code` `` 抠成占位符，处理完再放回去 |
