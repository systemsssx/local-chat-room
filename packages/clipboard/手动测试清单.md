# 手动测试清单

> **启动**：双击 `启动服务.cmd`（会自动打开浏览器；关掉那个黑窗口 = 停止服务）
> **每一项都写清「怎么做」和「应该看到什么」** —— 不通过就把那一步记下来，回头逐个修。

## 准备

1. 电脑浏览器打开 `http://localhost:8000`
2. 手机连**同一个 WiFi**，浏览器打开启动窗口里打印的那个地址（形如 `http://192.168.1.14:8000`）
3. 两边都输入相同房间号（默认 `1001`）

> 页面左下角会提示"手机访问 http://192.168.1.14:8000" —— 那就是手机该输的地址。

---

## A. 三种传输各自能不能通（左侧栏 01 / 02 / 03）

| # | 怎么做 | 应该看到什么 |
| --- | --- | --- |
| A1 | 左栏点 **CH1 HTTP 轮询**，在电脑上发一条 | 消息立刻出现；左下"状态"显示"轮询中 · 1.5s 一次" |
| A2 | 用手机也发一条 | 电脑这边**最慢 1.5 秒**内出现（轮询的延迟就是这个量级） |
| A3 | 左栏切到 **CH2 SSE 推送**，发一条 | 顶栏组合变成「CH2 · SSE 推送 × 纯文字」；**历史一条都没少** |
| A4 | 用手机发一条 | 电脑**几乎立刻**收到（服务器主动推） |
| A5 | 左栏切到 **CH3 WebSocket**，发一条 | 组合变 CH3；历史仍在 |
| A6 | 用手机发一条 | 电脑立刻收到 |

> **重点看**：每次切换传输，信息窗口的历史**不能清空、也不能重复**。
> 每条消息左侧有个小标签写着它是从哪条管道来的（`POLL` / `SSE` / `WS`）。

---

## B. 两种输入模式（顶栏选择栏）

| # | 怎么做 | 应该看到什么 |
| --- | --- | --- |
| B1 | 顶栏点 **剪贴板读取** | 底部输入框**消失**，换成一条"正在监听本机剪贴板"的状态条 |
| B2 | 电脑上随便复制一段文字（Ctrl+C） | **1 秒内**这条内容自动出现在信息窗口里，带 `CLIP` 标签 |
| B3 | 顶栏切回 **纯文字** | 输入框回来 |
| B4 | 顶栏组合显示 | 应该是「CH× · ××」两段，来回切都能对得上 |

> ⚠️ **剪贴板模式只在电脑上（localhost）可用**。手机上打开时会明确提示"当前环境不支持"，
> 这是浏览器的安全上下文限制，不是 bug。

## C. 三种消息类型

| # | 怎么做 | 应该看到什么 |
| --- | --- | --- |
| C1 | 输入文字 → Enter | 文字消息 |
| C2 | 点「图片」选一张 png/jpg | 图片显示为**缩略图**，下面是文件名、尺寸、大小、「下载」 |
| C3 | 点「文件」选一个 `.py` 或 `.txt` | 文件卡片：扩展名图标 + 文件名 + 大小 + 行数 + 编码；**下面带一段代码预览** |
| C4 | 随便选一个 `.zip` 或 `.exe` | **被拒绝**，提示"只接受图片或纯文本文件" |
| C5 | 在输入框里直接 **Ctrl+V 粘贴一张截图** | 直接上传并显示 |
| C6 | 手机上也发一张照片 | 电脑上能看到缩略图并点开 |

> 中文文件名要能**正确显示**（不能是 `ç¢é¢æªå¾.png` 这种乱码）。
> 用 Windows 记事本存一个中文 `.txt`（默认 GBK 编码）传上去，预览里的中文**不能乱码**。

## D. 局域网（手机 ↔ 电脑）

| # | 怎么做 | 应该看到什么 |
| --- | --- | --- |
| D1 | 手机浏览器打开 `http://192.168.1.14:8000` | 页面正常打开（不是转圈/超时） |
| D2 | 手机输入房间号 1001 | 能看到电脑上已经发的历史消息 |
| D3 | 右栏「在线成员」 | 应该能看到 **2 个人**（电脑 + 手机），各自带 IP 和当前用的传输方式 |
| D4 | 两边同时发消息 | 互不打架，都按顺序出现 |

> **连不上时的排查顺序**：① 服务窗口里打印的地址对不对 ② 手机是不是同一个 WiFi
> ③ Windows 防火墙有没有拦（首次运行弹窗要选"允许专用网络"） ④ 路由器有没有开 AP 隔离

## E. 历史与持久化

| # | 怎么做 | 应该看到什么 |
| --- | --- | --- |
| E1 | 右栏「历史记录」 | 最近几条 + 每条的「恢复」按钮 |
| E2 | 点某条的「恢复」 | 那条内容**作为新消息**发出来，手机上同步出现 |
| E3 | **关掉服务窗口，重新双击启动** | 启动横幅里"已存 N 条消息 / M 个房间"的数字**还在** |
| E4 | 刷新页面 | 之前的消息**全都还在**（从 SQLite 读回来的） |
| E5 | 看右栏「数据库」那一行 | 显示 `data/app.db · N KB` |

> **这一组是拓展任务的 6 条要求，也是最能拿分的一组。**
> 想看数据库里到底存了什么：另开一个命令行，跑 `node dev/db-inspect.mjs`（直接打开 `data/app.db` 打印两张表）。

## F. 边界与错误

| # | 怎么做 | 应该看到什么 |
| --- | --- | --- |
| F1 | 房间号输入 `中文` 或 `a b`，点「进入」 | 被拒绝并提示"房间号只能用字母、数字、下划线、短横" |
| F2 | 房间号输入 `2002` 点进入 | 进新房间，**看不到 1001 的消息**（房间隔离） |
| F3 | 传一个 **大于 2MB** 的图片 | 被拒绝，提示"文件超过 2MB" |
| F4 | 关掉服务，再刷新页面 | 顶栏状态变成错误提示（不是白屏 / 卡死） |
| F5 | 服务开着，把手机 WiFi 关掉 | 电脑这边不受影响；手机上显示连接已断开并自动重连 |
| F6 | 手机 WiFi 再打开 | 手机**自动重连**，并补齐断线期间的消息 |

## G. 已知限制（不是 bug，别当失败）

| 现象 | 原因 |
| --- | --- |
| 手机上「剪贴板读取」用不了 | 浏览器只在 localhost / HTTPS 下给剪贴板权限 |
| 手机页面在小屏上有点挤 | 界面按 1600×1000 桌面宽度设计的，还没做自适应 |
| 每次双击启动，端口被占会报错 | 上一次的窗口没关掉 —— 要么关掉它，要么 `python server.py --port 8001` |
| 历史面板只显示最近几条 | 题目要求是"最近 20 条"，接口支持 `?limit=20` |

## 发现问题时怎么记录

把这三样记下来，修起来最快：

1. **哪一步**（比如 D3）
2. **期望什么、实际看到什么**
3. 如果是页面问题：F12 → Console 有没有红字；Network 里那个请求的状态码是多少

服务窗口（黑窗口）里也会打日志，比如 `[sse] 张明 进入 1001 · 补齐 5 条 · 订阅者 2` —— 一眼能看出连接有没有建立。
