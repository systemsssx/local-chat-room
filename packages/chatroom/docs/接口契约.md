# 接口契约（v6 · 聊天室）

> 这份文件是**前后端唯一的约定**：改字段先改这里。
> 后端在 `app/`，前端在 `public/`，两边都按这一份写。

## 0. 一句话

登录拿 Cookie，Cookie 换身份，身份决定能进哪些房间；
房间靠**房间码**加入，消息靠 **SSE 单连接**推送。

---

## 1. 会话与鉴权

| 项 | 规定 |
| --- | --- |
| 凭据 | Cookie，名字 `sid`，值是 `secrets.token_urlsafe(32)` 的随机串 |
| 服务端存的 | `sessions` 表里存 **sid 的 sha256**（库被拿走也不能直接冒充登录） |
| Cookie 属性 | `HttpOnly; SameSite=Lax; Path=/; Max-Age=604800`；**只有 https 时才加 `Secure`**（局域网 http 演示不能加，加了 cookie 直接不落地） |
| 滑动续期 | 剩余不足 3 天时，每次访问自动续到 7 天 |
| 未登录访问 | 任何需要身份的接口返回 **401** `{"detail":"请先登录"}`；前端统一弹回登录页 |
| 不是成员 | 房间相关接口返回 **403** `{"detail":"你不在这个房间里"}` |
| 客户端不许传 | `userId`、`nickname` —— 服务端一律从会话里取，传了也忽略 |

**身份来源永远是：`cookie(sid)` → `sessions` → `users.id`。**

---

## 2. 数据表

```sql
users(id, username UNIQUE COLLATE NOCASE, pass_hash, created_at)
sessions(sid_hash PK, user_id, created_at, expires_at, last_seen)
rooms(id, code UNIQUE, name, owner_id, visibility, created_at)
room_members(room_id, user_id, role, joined_at, last_read_seq)   -- PK(room_id, user_id)
messages(id, room_id, seq, user_id, at, type, text, file_json)   -- seq 是"房间内"递增
```

- 密码：`pbkdf2_sha256$<迭代数>$<盐hex>$<哈希hex>`，校验用 `hmac.compare_digest`；
- 房间码：6 位，字符集 `ABCDEFGHJKMNPQRSTUVWXYZ23456789`（去掉 `0 O 1 I L` 这些念不清的）；
- 隔离：**一张表 + 每行带 `room_id`**，不是一房一库。查询必须带 `room_id`，访问前必须先查 `room_members`。

---

## 3. 认证接口

```
POST /api/auth/register   {username, password}   → 201 {user}        注册成功即登录（下 Cookie）
POST /api/auth/login      {username, password}   → 200 {user}        密码错 401
POST /api/auth/logout                            → 204               删 session + 清 Cookie
GET  /api/auth/me                                → 200 {user} | 401
```

`user` = `{id, username, createdAt}`

规则：用户名 2–16 字符（中英文/数字/下划线）；密码至少 8 位；
同一用户名连续失败 5 次锁 60 秒；注册重名 → 409。

---

## 4. 房间接口

```
GET    /api/rooms                 → 200 {rooms:[...]}      我加入的房间（含未读数）
POST   /api/rooms   {name, visibility}  → 201 {room}       建群：创建者自动成为 owner + 成员
GET    /api/rooms/public?q=       → 200 {rooms:[...]}      公开房间（仍要凭码加入）
POST   /api/rooms/join  {code}    → 200 {room, joined}     凭码入群（幂等：已在群里 joined=false）
GET    /api/rooms/{id}            → 200 {room, members}    房间概况（仅成员）
POST   /api/rooms/{id}/leave      → 204                    退群（房主退群：把 owner 交给最早加入的成员）
POST   /api/rooms/{id}/code       → 200 {code}             重置房间码（仅房主）
DELETE /api/rooms/{id}            → 204                    解散房间（仅房主，消息一起删）
GET    /api/rooms/{id}/connections → 200 {roomId, sse, online, messages}   连接实况（仅成员）
```

`room`（列表项；`role` / `unread` / `online` 只在"我的房间列表"里有）：

```json
{
  "id": 3, "code": "K7M2QX", "name": "产品讨论", "visibility": "private",
  "ownerId": 7, "ownerName": "阿哲", "createdAt": 1696578000000,
  "role": "member", "members": 12, "unread": 3, "online": 2,
  "lastSeq": 1284, "lastAt": 1696578185123,
  "lastText": "林可：登录页那版我用手机试了下…"
}
```

`members[]`（房间详情 / 快照里）：`{userId, username, role, joinedAt, lastReadSeq, online}`

- `members` 是**成员数**（不是在线数，在线数走 members 接口）；
- `unread` = `lastSeq - last_read_seq`，进房间时后端自动清零；
- `visibility`：`private`（只能凭码进）/ `public`（名字能在公开列表里看到，**但加入仍然要房间码**）。

**公开房间列表不带 `code`**：列表里给了码，"凭码入群"对公开房间就成了一句空话（谁都能抄走）。
想进公开房间还是得问群主要码 —— 公开只意味着"看得见有这个房间"。

## 5. 消息接口（都要是房间成员）

```
GET  /api/snapshot/{roomId}?since=<seq>   → {room, messages, members, latestSeq, hasMore}
POST /api/messages/{roomId}  {type, text, file}  → 201 {message}
GET  /api/history/{roomId}?before=<seq>&limit=20 → {messages:[...], hasMore}   向上翻页
POST /api/upload             (multipart: roomId, file) → 201 {file}
GET  /uploads/{filename}                          → 文件本身（**要登录 + 是那个房间的成员**）
```

`message`：

```json
{
  "seq": 1284, "id": "uuid", "roomId": 3,
  "userId": 7, "username": "阿哲",
  "type": "text|image|file", "text": "……",
  "file": {"url":"/uploads/x.png","name":"x.png","size":1234,"mime":"image/png","kind":"image","lines":null,"preview":null},
  "at": 1696578185123
}
```

限制沿用旧规矩：单条文字 64KB、上传 2MB。

**上传与下载的三条硬规矩**（都是安全边界，不是可选项）：

1. **只收扩展名白名单里的文件**：图片（png/jpg/gif/webp）+ 一批纯文本（txt/md/py/js/json/…）。
   **故意不收 `.html` / `.htm` / `.svg` / `.xml`** —— 它们会被浏览器当页面/脚本执行，
   传到同源目录就是**存储型 XSS**（别人打开链接就在我们的源里跑他的脚本）；
2. **下载要走鉴权**：`GET /uploads/{name}` 先验登录、再验"你是不是那个房间的成员"（否则 `uploads/` 就是公开图床）；
   非图片一律 `Content-Disposition: attachment` + `text/plain` + `nosniff`，绝不给内联执行的机会；
3. **`file` 字段由服务端白名单重建**：`url` 必须是 `/uploads/<文件名>`，且那个文件**确实上传到了这个房间**；
   `name` 截断到 120 字、`preview` 截断到 2000 字、多余键一律丢掉。
   客户端说"这是一张图"不算数。

## 6. SSE（唯一的实时通道）

```
GET /api/sse?room=<roomId>      （都要登录；带 room 时必须先是该房间成员）
```

一条连接同时推两类事件：**当前房间**的 + **我这个用户**的。

| event | data | 什么时候 |
| --- | --- | --- |
| `hello` | `{user, roomId, members, latestSeq}` | 连接建立（含断线重连后的补齐起点） |
| `messages` | `{messages:[...]}` | 当前房间有新消息（连上时先把 `since` 之后的差额补一帧） |
| `members` | `{members:[...]}` | 房间成员/在线情况变化 |
| `rooms` | `{rooms:[...]}` | **我的房间列表**变了：被拉进群、被踢、房间改名/换码 |
| `room-updated` | `{roomId, members?, name?, code?, lastSeq?, lastAt?, lastText?}` | 别的房间有新消息或人数变了（只更新左栏那一行，不重拉整表） |
| `room-gone` | `{roomId}` | 房间被解散 |
| `ping` | `{}` | 20 秒心跳（防中间设备掐断） |

- 断线由浏览器 `EventSource` 自动重连；重连后前端带 `since=本地最大 seq` 拉一次差额；
- 房间切换 = 断开旧连接、按新 `room` 重连（一条连接只服务一个房间）。

---

## 7. 前端约定

- 所有地址用**相对路径**（`/api/...`），不写死 `localhost`；
- 唯一的传输是 SSE；`EventSource` 靠浏览器自动带 Cookie 完成鉴权，**不传 token**；
- 401 统一处理：任何接口 401 → 清本地状态 → 显示登录页；
- 页面状态只有两种：未登录（登录卡片）/ 已登录（房间列表 + 消息流）。
